## Root cause / สิ่งที่ตัดออก

- `MCPServer` initialize ใน Asset Import Worker และ batch process ทำให้ registry มี label `Main` ซ้ำกับ Editor จริง
- Node bridge เลือก instance ด้วยผลแรกจาก label และ poll PID เดิม จึงจับ worker ผิดตัวหรือ timeout แม้ Editor หลักเปิด server แล้ว
- auto-config สร้างเฉพาะ `.mcp.json` ของ Claude และข้าม Git/registry install; Codex ใช้ `config.toml`
- global bridge เลือกโปรเจกต์ไม่แน่นอนเมื่อเปิดหลาย Editor เพราะไม่มี stable project/instance identity
- retry resolve port ครั้งเดียว จึงยิง port เก่าหลัง domain reload หรือ port rebind
- `.mcp-active` มีเพียงข้อความ `active` ไม่มี project, PID, instance หรือ port จึงใช้เป็น connection truth ไม่ได้
- C# หา manifest จาก path เก่า `Tools/unity-mcp-server/commands.json` แทน `Server~/commands.json`
- REFUTED: ไม่ใช่ port zombie, Unity ปิด, Codex global config หาย, manifest 69 commands เสีย หรือ official Unity MCP ชน namespace

- `node --test Server~/test/*.test.js` และ Unity EditMode tests ผ่าน

- Setup รอบสองคืน `already configured`; custom config ที่ไม่ได้กด Repair ต้อง byte-identical
- Write gate ยังคง OFF หลัง auto-start และ mutation ขณะ OFF ต้องคืน `READ-ONLY`

## Implementation

- กัน Asset Import Worker/batch process และเพิ่ม presence v2 แบบ atomic พร้อม stable `instanceId` และ heartbeat
- เพิ่ม deterministic project/instance selection, `AMBIGUOUS`, `unity_connection_status`, `unity_connect` และ re-discovery ทุก retry
- เพิ่ม Codex Setup/Repair/Doctor ผ่าน CLI โดยไม่ทับ custom หรือ official `unityMCP` registration
