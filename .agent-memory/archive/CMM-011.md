# CMM-011 Multi-session reliability, managed Players and Main publication

**Status:** Complete — implemented and independently qualified on Windows Unity 6000.0.75f1.

## Implemented behavior

- Two active owned sessions use private saved-source projects, immutable build artifacts and independent windowed Players; one bounded headless build worker runs at a time.
- The dashboard exposes owner/session/run identity, elapsed time, build state, PID and close controls. Owner, local-user and OS closure produce durable reasons and best-effort owner-only Node MCP notifications.
- Private code/assets stay private until explicit review and publication. Running Players and other private workspaces remain pinned until explicit refresh/build/restart.
- New sessions capture immutable per-file Assets baselines outside caller-editable workspaces. Legacy sessions without a baseline fail explicitly; no baseline is fabricated from today's Main.
- `unity_workspace` supports immutable conflict previews, explicit hash-bound apply/status/cancel and pristine `refresh_from_main`. Main publication is Assets-only, including metadata/GUID checks; Packages, ProjectSettings and vendored edits are reported unsupported.
- Main operations share persisted ordering with snapshots/build starts. Admission is nonrunnable until a durable acceptance marker exists; failed admission cannot silently execute later.
- Journaled staging, backups, write intents and per-file pre/post identities support guarded recovery. Unexpected third-party content is preserved. Directory preflight includes excluded/hidden descendants; Main deletion is never recursive.
- Source application and compile outcomes are distinct. Compiler errors retain published source and diagnostics; advancing only published baseline paths permits a corrective private plan. Job identity and completion facts survive reload.
- Dirty Main scenes/target assets, Play Mode and active import/compilation defer publication. The workflow never saves unrelated user edits. Close never automatically publishes.
- Refresh asynchronously verifies pristine private source, forks a new generation and retains old source/artifacts. Identical refresh does not consume an activated generation.
- Ordinary interactive Windows 6000.0.75f1 needs no test flag. Normal batch workers remain inert; explicit batch supervisors are supported for automation. Other engines, including unrequalified 6000.5.10f1, fail closed for managed tools.
- Node instructions place managed-default gameplay routing in their first 254 characters. Shared Main Play requires explicit intent; connect/Ping creates no session, build or Player; no silent fallback or third-party MCP interception is claimed.

## Confirmed reliability causes and corrections

- Original bridge requests could time out before Unity dispatch and replay mutations; expired queued actions could later write. The queue now bounds 64 pending jobs, expires before execution, pumps four jobs/cooperative 5 ms, rechecks write permission and never blindly replays writes. Ordinary Node timeout is 30 seconds; safe-read retries are bounded.
- Consecutive successful same-source pings coalesce with count/latest time. Errors and intervening commands remain distinct.
- Bare embedded64 Unity controls reproduced native heap corruption for foreign MainModule enumeration after immediate disposal of a live creator Process. Native full-image queries retain PID/start-time/exact-executable checks without module enumeration; normal and forced-GC production controls passed.
- Embedded controls proved inherited listening sockets survived successful Stop/Join until child exit. Clearing Windows socket inheritance before Start releases/rebinds the same port while the child remains alive. No speculative Stop/thread rewrite was needed.
- Mono WindowsIdentity.User is unsupported; bounded trusted whoami SID lookup plus current-user-only inherited DACL avoids unnecessary owner reassignment.
- Short private LocalAppData roots and explicit 250-character API preflight address observed Mono file-read failures despite successful longer-path copies.
- Runtime and host heartbeat reads tolerate bounded transient sharing/invalid data. An active Main operation grants bounded compile/reload grace; queued waits do not extend it. Normal orphan timeout remains 90 seconds; an active operation can temporarily extend that bound.
- Unity blackTexture has alpha zero; disabling blending makes the owner badge opaque. Actual corrected frames passed.
- Mono SHA256 wrappers are managed and were slow. Large Windows byte/stream hashing now uses per-call BCrypt with identical SHA256 digests, explicit cleanup, no cached handles/fallback and borrowed-stream ownership preserved. Small/non-Windows hashing remains managed.
- The same 76 MiB transaction measured 50.050 s before optimization, 0.776 s in the implementation cohort and 0.923 s independently afterward. These are fixture measurements, not Baowan or all-hardware performance claims.
