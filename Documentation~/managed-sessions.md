# Managed testing sessions (Windows v1)

Managed sessions are enabled in ordinary interactive Windows Editors on the exact qualified Unity version **6000.0.75f1**, without a special launch flag. This qualification does not cover every Unity 6.0 release. Other versions fail closed for these four tools; existing inspection/editing tools remain available.

The implementation keeps the main Editor separate while windowed game Players execute private saved-source builds. Each session has its own editable project, `Library`, headless build project, artifact and run mailbox. No source changes automatically enter main or another session.

Open **AI Unity MCP Server > Managed Sessions**, or the matching button in Connections, to see owners, elapsed time, build revision/state, Player PIDs and close controls. The local user can close any owned test window. Closing preserves private source and does not rebuild by default.

Ordinary batch build workers do not initialize a managed host. Automated batch supervisors require the explicit `-aiMcpManagedSupervisor` flag and the same Windows/version checks. Unsupported versions receive `UNITY_VERSION_NOT_QUALIFIED`; Unity **6000.5.10f1** remains excluded after observed native failures and has not been requalified after the stability fixes. The qualification is limited to **6000.0.75f1**.

## Tool flow

Gameplay/testing run requests, including plain "run Unity", default to this caller-owned managed flow. Resume an existing owned session with its saved capability or register a new one; a connection or health/PING request alone must not create a session, build or Player. Use shared Main Editor `play_control` only when the user explicitly asks for Main Editor Play Mode. Unsupported managed versions, builds, companions or game adapters are reported explicitly; they never trigger a silent shared-Main fallback. These instructions guide AI clients using this connector. They do not parse natural language or intercept direct calls to legacy tools or third-party MCP servers.

1. Enable package write commands in the main Editor. Call `unity_session` with `action=register`, a display `label` and a unique `requestId`. Keep the returned `sessionId` and one-time secret `capability` private. The capability is never recorded in Activity. A display label is not ownership proof.
2. Poll `unity_session action=status` until `state=ready`. All later tools require that session ID and capability. Snapshot errors remain explicit. Polling does not automatically renew the lease; use `action=renew` before `leaseUntilUnixMs`.
3. Edit only `workspacePath`, or use `unity_workspace action=read/write` for bounded UTF-8 Assets files. Writes require a unique request ID and the last read `expectedHash`, or `missing`. Managed writes are locked while a build is pending. `changes` exposes a bounded private file inventory/export path. Use `integration_plan` to review conflict-checked Assets changes before explicitly publishing them with `integration_apply`; use `refresh_from_main` to adopt saved Main changes into pristine private source. Neither operation happens automatically.
4. Call `unity_player_build action=start` with a unique request ID, then poll `action=status` with the returned job ID. A single FIFO worker imports/builds one private project at a time. Saved enabled build scenes are required. The worker uses the main Editor's Unity executable and Windows standalone toolchain. Build failures include a retained worker log path.
5. Call `unity_player action=start` with a successful job ID and request ID. Poll status until the runtime companion is ready. Each Player visibly identifies its owner/run, runs at 30 FPS by default, and starts in a 640x360 window. Resolution is bounded.
6. `unity_player action=capture` returns a command ID. Poll status with run ID and command ID for the actual Player PNG. Node returns inline image content; other transports expose the local file path. `action=input` routes a named semantic command through an explicitly registered game adapter. Unsupported input fails explicitly; it never injects the desktop's shared keyboard/mouse.
7. Owner `action=close`, the dashboard Close button, and closing the OS Player window terminate only that run. When an owner registers or authenticates through the Node bridge, it also receives best-effort standard MCP `notifications/message` for its own `player_closed` events. The bridge watches the local registry directory without HTTP health/event polling, verifies the owner capability hash, sends only public event fields, and releases watchers on disconnect/lease expiry. A client that multiplexes chats must route by the public session ID. Native/CLI retain the explicit event-reading fallback; no chat identity is guessed.

Read `unity_session action=events` with `afterSequence` for durable sequenced terminal reasons, including user close, owner close, process exit and lease expiry. Events are retained across reconnect/reload, but receiving a notification does not guarantee the client's AI wakes. Check `cursorExpired` if an old event cursor exceeds retention.

Use a stable request ID when retrying the same accepted mutation. Reusing an ID intentionally returns its original receipt. Register issues its capability only once; if that reply is lost, the local user must close the retained session rather than issuing duplicate registrations with the same ID.

## Review, publication and explicit refresh

New registrations capture an immutable, versioned per-file/directory baseline outside the editable workspace. Assets hashes describe the bytes copied from Main, including binary files and `.meta` files. A separate portion records the initial private `Packages`, `ProjectSettings` and `ManagedVendor` content after local-package vendoring, so the rewritten initial manifest is not reported as an edit. Existing sessions without this captured baseline return `BASELINE_UNAVAILABLE`; current Main is never substituted for a missing baseline.

Call `unity_workspace action=integration_plan` with the session ID, capability and a unique request ID. The asynchronous response returns `planId` and `state=planning`. Poll `action=integration_status` with that plan ID. A ready preview returns its immutable `baselineHash` and `planHash`, full counts, and entries containing `path`, `operation` (`added`, `modified`, `deleted`), status (`ready`, `conflict`, `already_applied`, `unsupported`), and expected baseline/private/Main hashes. Identical changes already in Main are `already_applied`; competing changes are conflicts. Unrelated Main edits are counted separately and are not publication candidates. Private changes outside Assets are reported as unsupported entries, not silently omitted.

Status uses explicit pagination: `offset` defaults to zero, `limit` defaults to 100 and is capped at 500, `totalEntries` is the full count and `nextOffset` is null only at the end. Oversized inventories fail explicitly rather than returning a clipped plan. Changed Assets payloads are captured in the private sidecar; editing the workspace later cannot change that captured preview. The Main/private snapshot hashes describe the creation-time observations. Status returns the frozen preview, not a fresh inspection of current source; apply rechecks source expectations and payload integrity.

Preview requires an unexpired owner lease, even when the session is already closed. Closing does not renew that lease or reactivate a session. An expired owner capability cannot request or read a preview. A preview is allowed with Write Commands OFF because it never writes Main. Asset/meta pairs and GUIDs must be complete and unambiguous; path traversal, reparse points, known secret filenames, GUID collisions and file/directory replacements fail closed. New files and folders require their matching `.meta` files.

Publication is a separate, explicit `unity_workspace action=integration_apply` request with `planId`, the exact reviewed `planHash` and a unique `requestId`. It requires Write Commands ON and valid owner authority, including for retained closed source. Acceptance returns `operationId`; poll `integration_status` with that ID. A non-runnable pending receipt is persisted before a durable acceptance marker permits the job to run. Failed admission cannot leave a later runnable job; interrupted admission without a valid marker fails closed. Never replay an apply under a new request ID after a timeout: inspect the accepted operation. Main operations share one persisted FIFO with source snapshots and build starts: earlier work drains, later work waits. Dirty Main scenes or target assets, Play Mode and active import/compilation defer publication within its deadline; the tool never saves unrelated user changes.

`integration_cancel` with `operationId` and a stable `requestId` cancels an owned queued/preparing operation before source writes, including for a closed session with a valid owner lease. Cleanup is allowed with Write Commands OFF. After publication begins, cancellation reports `cancelAccepted=false` and retains the applied-source/validation facts; it never claims that source changes were undone.

Apply rechecks baseline identity, reviewed Main/private bytes, staged payloads, asset/meta pairing, GUIDs and directory descendants. Only Assets is published; unsupported scope changes and conflicts block the operation. Hidden or excluded Main children also prevent deletion of their enclosing folder. Source is staged and backed up outside the editable workspace, in the protected Main registry directory. A durable per-file journal records write intent and preimages/postimages. Controlled rollback restores only verified transaction postimages; an external third hash is preserved and reported as `recovery_required`. Interrupted partial writes are never automatically replayed. These are optimistic checks and per-file replacements, not a filesystem-wide transaction or a lock against uncooperative external writers.

Lease, Write Commands, baseline and acceptance authority are checked again immediately before the first source mutation, after preflight and journal intent. Once the first write starts, the transaction finishes or recovers truthfully rather than pretending a later lease expiry undid changes. Rollback checks the current Main identity again after backup preparation; a failure to persist rollback evidence is also `recovery_required`.

After source verification, publication advances a new immutable baseline only for the published or already-applied paths. Unrelated Main edits never become fabricated private changes. `sourceApplied=true` remains true even if subsequent compilation fails. Asset-only work reports `compile_not_required` after import; code work requires an observed compilation cycle and reports bounded diagnostics. A `compile_failed` status retains applied Main source and the advanced baseline: fix the private source, create a new preview and explicitly apply it. A missing completion or interrupted validation is reported as unknown/interrupted, never assumed successful. Status responses retain their structured fields through the Native adapter, including `failureCode`/`failureDetail` and diagnostics.

`refresh_from_main` is also explicit, requires a request ID and Write Commands ON, and accepts only pristine private source. It stages a fresh saved-Main workspace and verifies the old private source asynchronously before switching the workspace pointer. Old source and existing Players/artifacts remain retained and pinned. Detected private edits fail rather than being discarded; create a new session or preserve/review the edits. Concurrent direct filesystem edits during verification are unsupported; the operation also checks metadata and workspace generation before the pointer switch, and always preserves the old directory. Refreshing identical content reports `workspace_unchanged` and does not consume another activated workspace generation. Rebuild and restart explicitly to run the refreshed code.

The dashboard offers explicit Review and Apply controls, gated by Write Commands, and a pristine-source refresh action. This is trusted local user authority, separate from an expired remote capability. Closing a Player or session remains close-only and never publishes source.

Bounds: four previews per current baseline, 32 immutable preview records per session and one active preview job globally; 50,000 inventory/change entries, 256 MiB per source file, 16 GiB source and 32 MiB per metadata document. Apply is limited to 512 changed entries and 512 MiB desired file bytes, supporting individual assets up to the existing 256 MiB file limit. Four Main operations may wait; 64 operation records and four activated workspace generations are retained. Preparation, backups and retained generations count toward the existing 64 GiB launch budget. Main operations have a 20-minute queue/preparation deadline. The synchronous filesystem commit can pause the Editor, especially for large assets; no low-latency claim is made for an unmeasured project.

Before active Main source I/O/import/compilation, the supervisor grants Players a fixed ten-minute recovery deadline. Queued jobs and dirty-scene waits do not extend that lease. Reload uses the same persisted deadline. The companion retains the largest valid timestamp it observes, so the temporarily longer orphan grace cannot be immediately shortened after a fast operation. Runtime protocol and ordinary 90-second orphan handling are unchanged outside this bounded Main operation grace.

## Source and dependency boundaries

Snapshots include saved files in `Assets`, `Packages`, `ProjectSettings` and private vendored packages. Unsaved scenes and unsaved Inspector state are not captured. Main changes after registration are not synchronized. `snapshotReport` lists excluded paths within these scopes; known credential filenames/key extensions and transient directories are excluded. This is a bounded file policy, not a general secret detector.

Registry identity remains under the main project's `Library/AIUnityMCPServer/managed-sessions`. Physical workspaces, build projects/artifacts and mailboxes use short flat directories under the current user's local application data, `AIUnityMCPServer/s/<project-hash>`. Both generated roots use a current-user-only inheritable Windows DACL, preserving ownership. Existing registered private source remains at its recorded path. Source/copy paths longer than 250 characters fail explicitly because Unity Mono file reads can fail even when a long-path copy succeeds.

Local `file:` UPM dependencies are copied into private `ManagedVendor` directories and their manifest references rewritten. Missing/archive dependencies, reparse points and transitive local-file dependencies are rejected. Registry/git packages resolve through the worker's private project; their normal caches/toolchain availability are still needed. Source fingerprints before/after copying reject concurrent edits during snapshotting. A running build uses its frozen copy, so later private edits do not change that artifact.

Builds and Player runs receive new IDs. Existing successful artifacts are retained and never overwritten by a later job. A rebuild/reopen is explicit: close the old Player, build the private source again, and start the chosen successful artifact. This workflow does not apply edited code instantly to a running Player. Main and other Players keep their original source/artifact revisions.

## Runtime opt-in

The `AIUnityMCPServer.Runtime` assembly is inert in ordinary runs. Its companion activates only in a standalone Player launched with a private run-configuration path. It reports readiness/heartbeat, takes end-of-frame screenshots, handles quit, and exits after 90 seconds without a valid supervisor heartbeat. Brief missing, malformed or locked observations retain the last valid lease; a later valid timestamp renews it. Domain reload grants an additional 60-second recovery grace period. Transient read warnings are throttled, and file readers permit atomic replacement.

Games can implement `AIUnityMCPServer.Runtime.IManagedPlayerInputAdapter`, register it with `ManagedPlayerApi.RegisterInputAdapter`, and unregister on destruction. The adapter declares supported names and returns a bounded string result. `ManagedPlayerApi.SaveDirectory` exposes a unique per-run directory for opt-in save handling. Separate processes isolate in-memory state; they do not automatically isolate PlayerPrefs, arbitrary save paths, accounts, ports or external backends.

Commands expire after 15 seconds in a responsive companion. If no result arrives by that deadline, status reports `outcome_unknown` with `retryable=false`; an already-started game action cannot be safely undone. Inspect the game state before retrying. Player status also exposes heartbeat age, and the owner/user can close an unresponsive owned process.

Optional status metadata is not process liveness. A temporarily unreadable/malformed Player heartbeat returns stable run identity/state with `heartbeatStatus=temporarily_unavailable`; it does not report the healthy process as dead or fail the entire status tool. Temporarily unreadable completed command metadata returns `result_unavailable`: retry status for the same command ID, never replay the action.

## Limits and recovery

- Two active sessions, one active Player per session and one build worker. Builds are FIFO by submission, including snapshot preparation.
- Up to 16 retained sessions, four build records and eight run records per session, 64 commands per run, 128 retained events and 256 mutation receipts per session. Capacity errors preserve existing private work.
- Snapshots are bounded to 50,000 files, 256 MiB per file and 16 GiB total. A background retained-storage check rejects new snapshots above 64 GiB; at least 1 GiB free disk is required. This is a launch budget, not a filesystem quota on arbitrary game code or Unity imports. Each session/build snapshot adds a physical source copy, so verify available disk for the actual project size before starting multiple large jobs.
- Session leases default to 30 minutes and can be renewed, with a two-hour maximum per renewal. Builds have a 20-minute deadline; Player readiness has a 60-second deadline. Close requests allow five seconds for graceful quit before stopping a verified owned executable/PID/start-time identity.
- Domain reload persists session/job/run/event identity. Interrupted copies fail explicitly; running workers/Players are polled after recovery. Editor shutdown closes owned processes. Private source remains until the user explicitly exports/cleans it. Do not remove active workspaces or artifacts.
- These are capability checks for this package's tools, not an OS sandbox. Arbitrary filesystem/Editor code execution and Unity built-in tools retain their own broader authority.

For automated batch supervision on the qualified Windows Editor version, `-aiMcpManagedSupervisor` enables the managed host. Ordinary interactive Editors need no flag. Normal managed build workers do not start a session supervisor.
